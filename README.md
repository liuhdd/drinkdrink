# 微醺账本

原生 HTML、CSS 和 JavaScript 实现的响应式 H5 酒局记账应用。服务端使用 Cloudflare Worker 与 D1，按登录用户保存数据。

## 功能

- 一次添加多位成员，分别设置昵称和初始待喝数量；支持编辑昵称、头像颜色与待喝数量，以及移除成员。
- 酒友按单行列表展示，左侧姓名，右侧待喝酒数；选中后在独立操作区加减酒、喝完一杯或编辑成员。
- 加减待喝数量；快捷加减步长可在酒局设置中调整。
- 开局时设置全员统一杯量；喝完一杯，从待喝中扣除本局杯量，同时增加已喝数量和杯数。
- 待喝数量不足一杯时禁用喝完按钮，避免出现负数。
- 单局排行榜按已喝「个数」降序排列，相同数量并列。
- 显示最近操作，支持撤销当前页面中最近 30 次成员操作。
- 新开一局清空计数与记录，可选择保留成员，并为所有成员应用新局设置的杯量。
- 新开一局前自动归档上一局，可在「历史酒局」查看当时的成员、计数、排行和最近 80 条操作记录；体验酒局不归档。
- 记住添加过的酒友，移除或新开局后仍可选择；添加弹窗支持多选以前的酒友，仅显示尚未加入本局的成员，可混合输入新酒友并分别设置初始待喝。
- 当前酒局、历史酒局和酒友名单保存到 D1，按平台登录用户隔离；成功保存后才更新页面，保存失败保留表单输入供重试。
- 同源页面通过 BroadcastChannel 和重新聚焦加载最新记录，版本检查防止旧页面覆盖新数据；遇到冲突会同步最新记录并提示重试。
- 首次读取服务端尚无记录时，自动迁移原 `cheers-ledger-v1` 本机记录（包括用户在体验局添加的真实成员），保留原始本机备份；已有服务端记录时以服务端为准。

初次打开为明确标记的体验酒局。在「设置」中点击「新开一局」即可开始自己的记录。
每杯与快捷加减数量支持 1–99 的整数，成员待喝和已喝分别最多 9999 个，每局最多 30 人。
旧版记录会将成员杯量统一为已有酒局设置，历史杯数、已喝数量和操作记录不重新换算。
同一账号可读取已保存记录；撤销记录在刷新后清空。此前旧版本新开局已经清除的历史无法恢复。
昵称在本局内不重复；编辑时也不能占用其他已保存酒友的昵称，避免合并成员身份。

## 本地运行

```sh
cd /Users/liuna/code/drinkdrink/site
npm ci
npm run dev
```

需要 Node.js 22.13+，推荐 Node.js 24+。访问 `http://127.0.0.1:4173/`。
本地预览使用 Node 内置 SQLite，以本机开发身份保存到忽略的 `.local-data/ledger.sqlite`，首次运行按生成的迁移初始化数据库。只监听本机；开发身份不会打包到线上 Worker。
旧版纯静态 HTTP 预览不再支持读写记录，需要上述服务端预览。

## 验证

```sh
npm test
node --check dist/app.mjs
npm run build
```

前端源文件保留在 `dist/`；服务端源文件位于 `server/worker.mjs`。构建生成 `dist/client/`、`dist/server/index.js` 与迁移元数据，不覆盖前端源文件。
数据库模型在 `db/schema.ts`，使用 `npm run db:generate` 生成追加迁移。已发布迁移不可修改。
托管配置 `.openai/hosting.json` 声明逻辑 D1 绑定 `DB`，由 Sites 发布服务分配数据库、应用迁移和注入运行时绑定。
`/api/ledger` 使用平台提供的 `oai-authenticated-user-id` 作为用户键；匿名访问拒绝。GET 返回数据及版本，PUT 用版本条件原子保存，过期版本返回 409 与最新数据。生产鉴权依赖 Sites dispatch，保留原网站访问范围。
